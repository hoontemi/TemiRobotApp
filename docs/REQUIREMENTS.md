# Temi 도서관 안내 앱 요구사항

## 1. 프로젝트 개요

본 프로젝트는 Temi 서비스 로봇에서 실행되는 도서관 안내용 Android 애플리케이션을 개발하는 것을 목적으로 한다.

이용자는 Temi 화면을 통해 다음 서비스를 이용할 수 있어야 한다.

- 도서관 시설 위치 안내
- 주요 시설까지 로봇 동행 안내
- 도서관 이용방법 안내
- 어린이 대상 체험형 콘텐츠
- 도서관 행사 및 프로그램 안내

앱은 어린이, 고령층 및 디지털 기기 사용이 익숙하지 않은 이용자도 쉽게 사용할 수 있도록 큰 버튼, 짧은 문장 및 단순한 화면 구조를 사용한다.

---

## 2. 개발 환경

- 개발 도구: Android Studio
- 개발 지원 도구: Claude Code
- 개발 언어: Kotlin
- UI 프레임워크: Jetpack Compose
- 화면 이동: Navigation Compose
- 상태 관리: ViewModel 및 StateFlow
- 로컬 데이터 저장: Room Database 또는 DataStore
- 로봇 연동: Temi SDK
- 최소 Android SDK: API 26 이상
- 대상 장치: Temi 로봇 내장 Android 화면
- 기준 화면: 약 13.3인치 가로형 화면

---

## 3. 개발 기본 원칙

### 3.1 데이터 하드코딩 금지

다음 값은 코드에 고정하지 않는다.

- 도서관 이름
- 시설 이름
- 시설 층수
- 시설 안내 문구
- Temi POI 이름
- 이용 안내 내용
- 어린이 퀴즈
- 추천도서
- 행사 정보
- 음성 안내 문구
- 복귀 위치
- 무입력 시간

모든 정보는 데이터 모델 또는 관리자 설정을 통해 변경할 수 있도록 구성한다.

### 3.2 도서관 이름 변경 가능

기획서에 표시된 특정 도서관 이름은 화면 디자인 예시로만 사용한다.

실제 앱에서는 관리자가 다음 값을 입력하거나 수정할 수 있어야 한다.

- 도서관 이름
- 환영 문구
- 도서관 로고
- 대표 안내 문구

### 3.3 POI 동적 연동

시설 안내에 사용하는 위치는 코드에 고정하지 않는다.

Temi에 등록된 POI 목록을 불러와 관리자가 시설과 POI를 연결할 수 있어야 한다.

POI가 새로 추가되거나 삭제된 경우 관리자 화면에서 최신 목록을 다시 불러올 수 있어야 한다.

### 3.4 UI 설계 원칙

- 화면은 기획서의 화이트·민트 계열 디자인을 참고한다.
- 버튼은 크고 명확하게 표시한다.
- 한 화면에 지나치게 많은 정보를 표시하지 않는다.
- 안내 문장은 짧고 이해하기 쉽게 작성한다.
- 주요 버튼에는 아이콘과 텍스트를 함께 사용한다.
- 어린이와 고령층이 쉽게 조작할 수 있도록 터치 영역을 크게 구성한다.
- 화면마다 기능의 목적을 명확하게 표시한다.
- 동일 기능의 버튼 스타일은 통일한다.

### 3.5 공통 상단바

홈 화면을 제외한 모든 하위 화면에는 공통 상단바를 표시한다.

공통 상단바 구성:

- 왼쪽: 뒤로가기 버튼
- 가운데: 현재 화면 제목
- 오른쪽: 홈 버튼

홈 버튼을 누르면 현재 기능을 종료하고 메인 화면으로 이동한다.

로봇이 이동 중인 상태에서 홈 버튼을 누르면 이동 취소 여부를 확인한 후 메인 화면으로 이동한다.

메인 화면에는 다음 정보를 표시한다.

- 도서관 이름
- 환영 문구
- 대표 메뉴 버튼
- 관리자 진입 버튼
- Temi 연결 상태

대표 메뉴는 다음과 같이 구성한다.

1. 시설을 찾고 있어요
2. 이용방법이 궁금해요
3. 로봇과 놀아요
4. 오늘의 행사

각 메뉴는 큰 버튼으로 구성하며 아이콘과 텍스트를 함께 표시한다.

## 6. 시설 안내 기능

### 6.1 시설 목록 화면

시설 안내 메뉴를 선택하면 관리자가 등록한 시설 목록을 표시한다.

시설 목록의 예시는 다음과 같으나 실제 항목은 관리자 설정에 따라 달라질 수 있다.

- 어린이자료실
- 종합자료실
- 디지털자료실
- 열람실
- 안내데스크
- 무인반납기
- 엘리베이터
- 화장실

각 시설은 다음 정보를 가진다.

- 시설 ID
- 시설 이름
- 시설 설명
- 층수
- 연결된 Temi POI
- 동행 안내 가능 여부
- 위치 안내 문구
- TTS 문구
- 아이콘
- 활성화 여부
- 표시 순서

### 6.2 시설 검색

시설 수가 많을 경우 다음 기능을 제공한다.

- 시설명 검색
- 층별 필터
- 카테고리 필터
- 전체 시설 보기

### 6.3 안내 방식 선택

시설을 선택하면 시설 정보와 이용 가능한 안내 방식을 표시한다.

가능한 안내 방식:

- 동행 안내
- 위치만 보기
- 관련 안내 듣기

### 6.4 동행 안내

동행 안내를 선택하면 다음 순서로 동작한다.

1. 목적지와 안내 내용을 표시한다.
2. Temi가 출발 안내 TTS를 실행한다.
3. 연결된 POI로 이동한다.
4. 이동 상태 화면을 표시한다.
5. 목적지 도착 시 도착 안내 TTS를 실행한다.
6. 일정 시간 후 홈 화면으로 이동하거나 복귀 POI로 이동한다.

### 6.5 다른 층 시설 안내

Temi가 직접 이동할 수 없는 다른 층 시설은 다음과 같이 안내한다.

- 시설이 위치한 층 표시
- 엘리베이터 또는 계단 방향 표시
- 관리자 입력 안내 문구 표시
- 필요한 경우 엘리베이터 앞 POI까지 동행 안내

### 6.6 POI 미등록 처리

시설에 연결된 POI가 없을 경우:

- 위치 설명만 제공한다.
- 동행 안내 버튼을 비활성화한다.
- 일반 이용자에게는 자연스러운 안내 문구를 표시한다.
- 관리자 화면에는 POI 미등록 상태를 표시한다.

## 7. 도서관 이용방법 안내

이용방법 안내는 반복 문의가 많은 정보를 간결하게 제공한다.

기본 카테고리 예시:

- 책 대출·반납
- 회원가입
- 회원증
- 열람실 이용
- 운영시간
- 휴관일
- 대출 가능 권수
- 대출 기간
- 연장 및 예약
- 무인반납 방법

각 안내 정보는 다음 항목을 가진다.

- 카테고리
- 제목
- 짧은 답변
- 상세 답변
- 음성 안내 문구
- 관련 시설
- 관련 POI
- 활성화 여부
- 표시 순서

세부 안내 화면에는 다음 버튼을 제공할 수 있다.

- 안내 듣기
- 관련 시설 안내
- 직원 도움 안내
- 홈으로 이동

---

## 8. 어린이 콘텐츠

어린이 콘텐츠는 체험형 구조로 제공한다.

기본 콘텐츠:

- 오늘의 퀴즈
- 추천도서
- 도서관 예절
- 어린이자료실 안내

### 8.1 오늘의 퀴즈

퀴즈는 다음 항목을 가진다.

- 퀴즈 ID
- 분야
- 문제
- 보기
- 정답
- 정답 설명
- 관련 추천도서
- 관련 시설
- 활성화 여부

퀴즈 진행 순서:

1. 퀴즈 분야 선택
2. 문제 표시
3. 답안 선택
4. 정답 또는 오답 결과 표시
5. 짧은 음성 반응 실행
6. 정답 설명 표시
7. 다른 퀴즈 또는 관련 콘텐츠로 이동

### 8.2 추천도서

추천도서는 다음 정보를 표시한다.

- 책 제목
- 저자
- 표지 이미지
- 짧은 소개
- 대상 연령
- 관련 주제
- 소장 위치 안내
- 어린이자료실 안내 버튼

### 8.3 도서관 예절

도서관 예절은 어린이가 쉽게 이해할 수 있는 카드 또는 퀴즈 형태로 제공한다.

예시:

- 도서관에서는 조용히 하기
- 책을 깨끗하게 사용하기
- 읽은 책은 지정된 장소에 두기
- 뛰지 않기
- 다른 이용자를 배려하기

## 9. 오늘의 행사

행사 화면에는 관리자가 등록한 행사 및 프로그램을 표시한다.

행사 정보 항목:

- 행사명
- 행사 설명
- 행사 일자
- 시작 시간
- 종료 시간
- 장소
- 대상
- 신청 방법
- QR 코드 또는 안내 URL
- 관련 시설
- 활성화 여부

행사가 없을 경우 빈 화면 대신 다음과 같은 안내 문구를 표시한다.

"현재 등록된 행사가 없습니다."

## 10. 관리자 기능

### 10.1 관리자 진입

- 관리자 버튼은 일반 사용자에게 방해되지 않는 위치에 배치한다.
- 관리자 화면 진입 시 비밀번호를 확인한다.
- 비밀번호 연속 오류 시 일정 시간 입력을 제한할 수 있다.

### 10.2 도서관 기본정보 관리

관리 가능한 항목:

- 도서관 이름
- 환영 문구
- 로고
- 안내 문구
- 대표 이미지

### 10.3 시설 관리

관리자는 다음 작업을 수행할 수 있다.

- 시설 추가
- 시설 수정
- 시설 삭제
- 시설 활성화 및 비활성화
- 표시 순서 변경
- 층수 설정
- POI 연결
- 동행 안내 가능 여부 설정
- 화면 안내 문구 수정
- TTS 문구 수정

### 10.4 POI 관리

- Temi에 등록된 POI 목록을 불러온다.
- POI 목록을 새로고침할 수 있다.
- 시설과 POI를 연결할 수 있다.
- 복귀 위치를 선택할 수 있다.
- 삭제되거나 존재하지 않는 POI를 표시한다.

### 10.5 콘텐츠 관리

관리자는 다음 콘텐츠를 추가, 수정, 삭제할 수 있다.

- 이용방법 안내
- 퀴즈
- 추천도서
- 도서관 예절
- 행사 정보

## 11. Temi SDK 연동 요구사항

Temi 관련 기능은 UI 코드와 분리하여 관리한다.

필요 기능:

- Temi 서비스 연결 상태 확인
- SDK 권한 확인
- POI 목록 조회
- 목적지 이동
- 이동 중지
- 이동 상태 수신
- 도착 상태 수신
- 이동 실패 처리
- TTS 실행
- TTS 완료 상태 수신
- 복귀 POI 이동

화면에서 Temi SDK를 직접 호출하지 않는다.

Temi 제어는 별도의 Manager 또는 Repository를 통해 수행한다.

권장 클래스:

- TemiRobotManager
- TemiNavigationManager
- TemiTtsManager
- TemiPoiRepository
- TemiConnectionState
- TemiNavigationState

## 12. 이동 상태 화면

로봇이 이동 중일 때 전용 상태 화면 또는 팝업을 표시한다.

표시 정보:

- 목적지 이름
- 이동 중 상태
- 안내 문구
- 이동 중지 버튼
- 홈 버튼

이동 상태 예시:

- 이동 준비 중
- 이동 중
- 목적지 도착
- 이동 일시 중단
- 이동 취소
- 이동 실패
- 목적지를 찾을 수 없음

이동 실패 시 사용자가 선택할 수 있는 기능:

- 다시 시도
- 위치만 보기
- 홈으로 이동

---

## 13. TTS 요구사항

- 안내 문구를 Temi 음성으로 출력할 수 있어야 한다.
- TTS 실행 중 동일 음성이 중복 실행되지 않아야 한다.
- 화면을 종료하거나 다른 기능으로 이동할 때 필요한 경우 TTS를 중지한다.
- TTS 완료 후 다음 동작을 실행할 수 있어야 한다.
- 시설별 TTS 문구는 관리자 화면에서 변경할 수 있어야 한다.

---

## 14. 자동 복귀 및 무입력 처리

관리자는 무입력 자동 복귀 시간을 설정할 수 있어야 한다.

기본 동작:

1. 사용자의 입력이 일정 시간 없으면 경고 팝업을 표시한다.
2. 추가 입력이 없으면 홈 화면으로 이동한다.
3. 설정에 따라 복귀 POI로 이동한다.

다음 상황은 무입력 복귀에서 제외하거나 별도 처리한다.

- 로봇 이동 중
- TTS 안내 중
- 관리자 설정 중
- 퀴즈 결과 표시 중
- 오류 팝업 표시 중

---

## 15. 오류 및 예외 처리

다음 상황에 대한 예외 처리가 필요하다.

- Temi SDK 연결 실패
- 로봇 권한 미승인
- POI 목록 조회 실패
- 등록된 POI 없음
- 선택한 POI 삭제됨
- 목적지 이동 실패
- 이동 중 장애물 발생
- TTS 실행 실패
- 저장 데이터 손상
- 이미지 파일 누락
- 네트워크 연결 실패
- 행사 QR 코드 로딩 실패

오류 메시지는 기술적인 코드보다 사용자가 이해하기 쉬운 문장으로 표시한다.

---

## 16. 데이터 저장

초기 버전은 태블릿 내부에 데이터를 저장한다.

저장 대상:

- 도서관 기본 설정
- 시설 정보
- POI 연결 정보
- 이용 안내
- 어린이 콘텐츠
- 행사 정보
- 관리자 설정
- 복귀 위치
- 무입력 시간

향후 서버 기반 관리자 페이지와 동기화할 수 있도록 Repository 구조를 사용한다.

---

## 17. 디자인 요구사항

- 화이트 배경을 기본으로 사용한다.
- 민트 또는 청록 계열을 강조 색상으로 사용한다.
- 버튼 모서리는 부드러운 라운드 형태로 구성한다.
- 주요 버튼에는 충분한 여백을 적용한다.
- 글자 크기는 Temi 화면에서 멀리서도 읽을 수 있도록 설정한다.
- 화면마다 버튼 크기와 간격을 통일한다.
- PDF 기획안의 전체적인 분위기와 구조를 참고한다.
- PDF 이미지를 그대로 복사하지 않고 앱 화면에 적합하게 재구성한다.

---

## 18. 비기능 요구사항

- 앱 실행 중 강제 종료가 발생하지 않아야 한다.
- 화면 전환 시 눈에 띄는 지연이 없어야 한다.
- 버튼을 연속으로 눌러도 기능이 중복 실행되지 않아야 한다.
- 장시간 대기 후에도 정상 작동해야 한다.
- Temi 재부팅 후 앱을 다시 실행할 수 있어야 한다.
- 설정 데이터는 앱 재시작 후에도 유지되어야 한다.
- 실제 Temi가 연결되지 않은 개발 환경에서는 FakeRepository로 UI 테스트가 가능해야 한다.

---

## 19. 초기 개발 범위

1차 개발에서는 다음 기능을 구현한다.

- 전체 화면 UI
- 화면 간 이동
- 공통 상단바
- FakeRepository 기반 샘플 데이터
- 시설 안내 화면
- 이용방법 화면
- 어린이 콘텐츠 화면
- 행사 화면
- 기본 관리자 화면

1차 개발에서는 다음 기능을 제외한다.

- 실제 Temi 이동
- 실제 Temi TTS
- 서버 연동
- 원격 관리자 페이지
- 통계 서버 전송

Temi SDK 연동은 전체 UI와 데이터 구조가 확정된 후 진행한다.

## 20. 완료 기준

다음 조건을 모두 충족하면 초기 UI 개발이 완료된 것으로 판단한다.

- 앱이 정상 빌드된다.
- 홈 화면의 모든 메뉴가 작동한다.
- 모든 하위 화면에 뒤로가기와 홈 버튼이 표시된다.
- 시설 목록과 상세 화면이 표시된다.
- 이용방법 카테고리와 답변 화면이 표시된다.
- 어린이 퀴즈를 진행할 수 있다.
- 행사 목록과 상세 내용을 확인할 수 있다.
- 화면 데이터가 코드에 직접 하드코딩되지 않고 Repository에서 제공된다.
- 실제 Temi 없이도 전체 화면 흐름을 테스트할 수 있다.
