# Temi 도서관 안내 앱 화면 흐름

본 문서는 `REQUIREMENTS.md`에 정의된 요구사항을 기준으로 작성한 화면 흐름 문서다.

도서관 이름, 시설명, 시설 층수, POI 이름 등은 모두 관리자가 등록·수정하는 값이며,
이 문서에 등장하는 예시 명칭(예: 어린이자료실, 안내데스크 등)은 REQUIREMENTS.md의 예시를
그대로 인용한 것으로, 코드에 고정되는 값이 아니다. 실제 표시값은 관리자 설정 데이터를 따른다.

이 문서 안에서 "N. 제목" 또는 "N.N 제목" 형태의 인용(예: `"3.2 시설 상세"`)은
모두 **이 문서(SCREEN_FLOW.md) 자신의 목차 번호**를 가리킨다. REQUIREMENTS.md를
가리킬 때는 번호 대신 항상 `REQUIREMENTS.md의 "제목"` 형식으로 표기하여 두 문서의
번호 체계가 서로 섞이지 않도록 한다.

## 1. 앱 실행 및 초기 로딩

```text
앱 실행
  ↓
초기 로딩 화면
  ├─ 도서관 기본정보 로딩 (관리자 설정 데이터)
  ├─ Temi 서비스 연결 상태 확인
  └─ SDK 권한 확인
  ↓
연결/로딩 정상?
  ├─ [예] → 메인 화면
  └─ [아니오] → "11. Temi 연결 실패, POI 오류, 이동 오류" 흐름으로 이동
```

*(REQUIREMENTS.md의 "개발 환경", "Temi SDK 연동 요구사항", "오류 및 예외 처리" 참고)*

## 2. 메인 화면

```text
메인 화면
  ├─ [도서관 이름] (관리자 설정값)
  ├─ [환영 문구] (관리자 설정값)
  ├─ Temi 연결 상태 표시
  ├─ 대표 메뉴 버튼
  │    ├─ 1) 시설을 찾고 있어요      → "3. 시설 안내" 흐름
  │    ├─ 2) 이용방법이 궁금해요     → "4. 도서관 이용방법 안내" 흐름
  │    ├─ 3) 로봇과 놀아요           → "5. 어린이 콘텐츠" 흐름
  │    └─ 4) 오늘의 행사             → "6. 오늘의 행사" 흐름
  └─ 관리자 진입 버튼                → "7. 관리자" 흐름 (7.1 비밀번호부터 시작)
```

*(REQUIREMENTS.md의 "메인 화면 요구사항" 참고)*

메인 화면은 공통 상단바가 표시되지 않는 유일한 화면이다. *(REQUIREMENTS.md의 "공통 상단바" 참고)*

## 3. 시설 안내

### 3.1 시설 목록

```text
메인 화면 → "시설을 찾고 있어요" 선택
  ↓
시설 목록 화면 [공통 상단바: ← | 시설 안내 | 홈]
  ├─ 관리자가 등록한 시설 목록 표시 (예: 어린이자료실, 종합자료실, 안내데스크 등 — 관리자 설정값)
  ├─ 시설명 검색
  ├─ 층별 필터
  ├─ 카테고리 필터
  ├─ 전체 시설 보기
  ↓
시설 선택
  ↓
"3.2 시설 상세" 로 이동
```

*(REQUIREMENTS.md의 "시설 목록 화면", "시설 검색" 참고)*

### 3.2 시설 상세

```text
시설 상세 화면 [공통 상단바: ← | [시설명] | 홈]
  ├─ 시설 이름 / 시설 설명 / 층수 / 아이콘 표시
  ├─ 위치 안내 문구 표시
  ↓
연결된 POI 존재 여부
  ├─ [POI 있음] → 안내 방식 선택 화면 표시 (아래 3가지 중 하나만 선택)
  │     ├─ 동행 안내   → "3.3 동행 안내"
  │     ├─ 위치만 보기 → "3.4 위치만 보기"
  │     └─ 안내 듣기   → 위치 안내 문구를 TTS로 재생 (화면 전환 없음,
  │                       TTS 공통 규칙은 "8.2 TTS 중지 및 중복 실행 방지" 참고)
  └─ [POI 없음] → "3.5 POI 미등록" 흐름으로 이동
```

*(REQUIREMENTS.md의 "안내 방식 선택"(원문의 "관련 안내 듣기"를 본 문서에서는
"안내 듣기"로 표기), "POI 미등록 처리" 참고)*

안내 방식은 항상 "동행 안내 / 위치만 보기 / 안내 듣기" 3가지로 고정하며,
서로 배타적인 선택지다. "3.4 위치만 보기" 내부의 안내 듣기 보조 버튼은
새로운 4번째 안내 방식이 아니라 이 "안내 듣기"와 동일한 동작이다.

같은 층이 아닌 시설을 선택한 경우, 시설 상세 진입 시 "3.6 다른 층 시설 안내"를 함께 표시한다.

### 3.3 동행 안내

```text
동행 안내 선택
  ↓
목적지 및 안내 내용 표시
  ↓
Temi 출발 안내 TTS 실행 (TTS 공통 규칙: "8.2 TTS 중지 및 중복 실행 방지" 적용)
  ↓
연결된 POI로 이동 시작
  ↓
"3.7 이동 중" 화면으로 전환
```

*(REQUIREMENTS.md의 "동행 안내" 1~3단계 참고)*

### 3.4 위치만 보기

```text
위치만 보기 선택
  ↓
시설 위치 안내 화면
  ├─ 시설 층수 / 위치 설명 문구 표시
  └─ 안내 듣기 보조 버튼
       (별도의 새로운 안내 방식이 아니라, "3.2 시설 상세"의 "안내 듣기"와
        동일한 TTS 재생 동작을 이 화면에서도 보조적으로 제공하는 것)
  ↓
사용자 선택
  ├─ 뒤로가기 → "3.2 시설 상세"
  └─ 홈 버튼 → "8.1 뒤로가기와 홈 버튼" 흐름
```

*(REQUIREMENTS.md의 "안내 방식 선택" 중 위치만 보기 참고)*

### 3.5 POI 미등록

```text
시설에 연결된 POI 없음
  ↓
POI 미등록 안내 화면
  ├─ 위치 설명만 제공 (텍스트 기반)
  ├─ 동행 안내 버튼 비활성화 처리
  └─ 자연스러운 안내 문구 표시 (기술적 오류 문구 아님)

※ 관리자 화면("7.5 POI 연결")에는 해당 시설이 "POI 미등록" 상태로 별도 표시된다.
```

*(REQUIREMENTS.md의 "POI 미등록 처리" 참고)*

### 3.6 다른 층 시설 안내

```text
선택한 시설이 Temi가 이동 불가능한 다른 층에 위치
  ↓
다른 층 시설 안내 화면
  ├─ 시설이 위치한 층 표시
  ├─ 엘리베이터 또는 계단 방향 표시
  ├─ 관리자 입력 안내 문구 표시
  └─ (필요 시) 엘리베이터 앞 POI까지 동행 안내 제공
       ↓
      "3.3 동행 안내" 흐름 재사용 (목적지 = 엘리베이터 앞 POI)
```

*(REQUIREMENTS.md의 "다른 층 시설 안내" 참고)*

### 3.7 이동 중

```text
이동 상태 화면 / 팝업 [공통 상단바 대체: 홈 버튼 + 이동 중지 버튼]
  ├─ 목적지 이름 표시
  ├─ 이동 중 상태 표시 (이동 준비 중 / 이동 중 / 이동 일시 중단)
  ├─ 안내 문구 표시
  ├─ 이동 중지 버튼
  └─ 홈 버튼
  ↓
상태 갱신
  ├─ [목적지 도착] → "3.8 이동 완료"
  ├─ [이동 실패 / 목적지를 찾을 수 없음] → "3.9 이동 실패 및 취소"
  ├─ [이동 중지 버튼 선택] → "3.9 이동 실패 및 취소" (이동 취소)
  └─ [홈 버튼 선택] → 이동 취소 여부 확인 팝업 → 확인 시 메인 화면
```

*(REQUIREMENTS.md의 "이동 상태 화면", "공통 상단바"의 이동 중 홈 버튼 예외 처리 참고)*

※ 1차 개발에서는 실제 이동이 아닌 FakeRepository 기반 가상 상태로 표현한다.
  자세한 내용은 "13.1 이동·TTS·POI 화면의 Fake 상태 처리" 참고.

### 3.8 이동 완료

```text
목적지 도착
  ↓
Temi 도착 안내 TTS 실행 (TTS 공통 규칙: "8.2 TTS 중지 및 중복 실행 방지" 적용)
  ↓
도착 안내 화면 표시
  ↓
일정 시간 경과
  ├─ [복귀 설정 없음] → 메인 화면으로 이동
  └─ [복귀 설정 있음] → "10. 복귀 POI 이동" 흐름
```

*(REQUIREMENTS.md의 "동행 안내" 4~6단계, "이동 상태 화면" 참고)*

### 3.9 이동 실패 및 취소

```text
이동 상태: 이동 실패 / 목적지를 찾을 수 없음 / 이동 취소
  ↓
이동 실패 안내 화면
  ├─ 다시 시도        → "3.3 동행 안내" 재실행
  ├─ 위치만 보기       → "3.4 위치만 보기"
  └─ 홈으로 이동       → 메인 화면
```

※ 1차 개발에서는 실제 이동 실패가 아닌 FakeRepository 기반 가상 상태로 표현한다.
  자세한 내용은 "13.1 이동·TTS·POI 화면의 Fake 상태 처리" 참고.

## 4. 도서관 이용방법 안내

### 4.1 카테고리

```text
메인 화면 → "이용방법이 궁금해요" 선택
  ↓
이용방법 카테고리 화면 [공통 상단바: ← | 이용방법 안내 | 홈]
  └─ 카테고리 목록 (4개 고정, 문구·순서·노출 여부는 관리자 설정값)
       책 대출·반납 / 회원가입 / 열람실 이용 / 운영시간
  ↓
카테고리 선택
  ↓
"4.2 세부 항목" 으로 이동
```

*(REQUIREMENTS.md의 "도서관 이용방법 안내" 참고)*

### 4.2 세부 항목

```text
세부 항목 목록 화면 [공통 상단바: ← | [카테고리명] | 홈]
  └─ 해당 카테고리에 속한 안내 항목 목록 (제목 단위)
  ↓
항목 선택
  ↓
"4.3 답변 화면" 으로 이동
```

*(REQUIREMENTS.md의 "도서관 이용방법 안내" 중 안내 정보 항목 구성 참고)*

### 4.3 답변 화면

```text
답변 화면 [공통 상단바: ← | [항목 제목] | 홈]
  ├─ 짧은 답변 표시
  ├─ 상세 답변 표시
  └─ 버튼
       ├─ 안내 듣기         → TTS로 음성 안내 문구 재생
       │                      (TTS 공통 규칙: "8.2 TTS 중지 및 중복 실행 방지" 적용)
       ├─ 관련 시설 안내     → "4.4 관련 시설·POI 연결"
       ├─ 직원 도움 안내     → 직원 호출/안내 문구 표시
       └─ 홈으로 이동        → 메인 화면
```

*(REQUIREMENTS.md의 "도서관 이용방법 안내" 중 세부 안내 화면 버튼 참고)*

### 4.4 관련 시설·POI 연결

```text
"관련 시설 안내" 버튼 선택
  ↓
답변에 연결된 데이터 확인
  ├─ [관련 시설 있음] → "3.2 시설 상세" 화면으로 이동 (해당 관련 시설 기준)
  ├─ [관련 시설 없음 + 관련 POI 있음] → 관련 POI 기준으로 처리
  │     ↓
  │    동행 안내 가능 여부 확인
  │     ├─ [가능] → "3.3 동행 안내" 흐름 (목적지 = 관련 POI)
  │     └─ [불가능] → 위치 정보만 표시 ("3.4 위치만 보기"와 동일한 화면 구성)
  └─ [관련 시설·관련 POI 모두 없음] → 버튼 비활성화 또는 미노출
```

※ 관련 시설과 관련 POI는 역할이 다르며 중복되지 않는다.
  - 관련 시설: "3.2 시설 상세" 화면으로 연결되어 시설의 전체 정보(설명, 층수,
    안내 방식 선택 등)를 보여준다.
  - 관련 POI: 시설 상세를 거치지 않고, 위치 안내 또는 동행 안내 가능 여부를
    판단하는 데 곧바로 사용되는 이동 지점 정보다.

*(REQUIREMENTS.md의 "도서관 이용방법 안내" 중 관련 시설·관련 POI 항목 참고)*

## 11. Temi 연결 실패, POI 오류, 이동 오류

```text
오류 발생 지점
  ├─ 앱 실행/초기 로딩 시
  │    ├─ Temi SDK 연결 실패      → 연결 재시도 안내 화면 표시
  │    └─ 로봇 권한 미승인         → 권한 안내 화면 표시
  │
  ├─ 시설 안내(3장) 진입/이용 중
  │    ├─ POI 목록 조회 실패       → 안내 문구 표시 + 다시 시도 버튼
  │    ├─ 등록된 POI 없음          → "3.5 POI 미등록" 흐름과 동일하게 처리
  │    └─ 선택한 POI 삭제됨        → 이동 시도 시 "이동 실패" 상태로 처리
  │                                   → "3.9 이동 실패 및 취소" 흐름
  │
  ├─ 이동(3.7 이동 중) 진행 중
  │    ├─ 목적지 이동 실패
  │    ├─ 이동 중 장애물 발생
  │    └─ 목적지를 찾을 수 없음
  │         ↓
  │        "3.9 이동 실패 및 취소" 흐름
  │         (다시 시도 / 위치만 보기 / 홈으로 이동 중 선택)
  │
  ├─ TTS 실행 중
  │    └─ TTS 실행 실패            → 화면 텍스트 안내로 대체, 다음 동작 정상 진행
  │
  └─ 기타
       ├─ 저장 데이터 손상         → 기본값 또는 안내 문구로 대체
       ├─ 이미지 파일 누락         → 기본 이미지로 대체
       ├─ 네트워크 연결 실패       → 오프라인 안내 문구 표시
       └─ 행사 QR 코드 로딩 실패   → QR 대신 안내 URL 텍스트 또는 오류 문구 표시

모든 오류 메시지는 기술적 코드 대신 사용자가 이해하기 쉬운 문장으로 표시한다.
```

## 12. Navigation Route 목록

아래 Route는 화면 흐름을 기준으로 정리한 논리적 이름이며, 실제 구현 시 세부 인자(예: 시설 ID, 카테고리 ID)는 데이터 모델에 맞춰 결정한다.

| 화면 | Route (예시) |
|---|---|
| 초기 로딩 | `splash` |
| 메인 화면 | `main` |
| 시설 목록 | `facility/list` |
| 시설 상세 | `facility/detail/{facilityId}` |
| 안내 방식 선택 | `facility/guideOptions/{facilityId}` |
| 위치만 보기 | `facility/viewOnly/{facilityId}` |
| POI 미등록 안내 | `facility/poiMissing/{facilityId}` |
| 다른 층 시설 안내 | `facility/otherFloor/{facilityId}` |
| 이동 중 | `navigation/moving/{destinationId}` |

### 13.1 이동·TTS·POI 화면의 Fake 상태 처리

3장(시설 안내)의 이동 관련 화면과 8.2(TTS 공통 규칙)의 화면은 1차 개발 범위에
**포함**되지만, 실제 Temi SDK를 호출하지 않고 FakeRepository의 가상 상태로만
동작한다는 점을 명확히 한다.

```text
이동 중 · 이동 완료 · 이동 실패 화면 (3.7 / 3.8 / 3.9)
  ├─ 화면 UI, 상태 표시, 버튼 동작은 1차 개발에 포함된다.
  └─ 실제 Temi 이동 대신 FakeRepository의 가상 상태로 동작한다.
       예: 이동 준비 중 → 가상 이동 중 → 가상 도착

TTS 관련 화면 (3.2 / 3.3 / 3.4 / 3.8 / 4.3 / 5.4, "8.2 TTS 중지 및 중복 실행 방지" 규칙)
  ├─ TTS 트리거 UI, 중지 처리, 중복 실행 방지 흐름은 1차 개발에 포함된다.
  └─ 실제 Temi TTS 호출 대신 FakeRepository의 가상 상태로 동작한다.
       예: TTS 대기 → 가상 재생 중 → 가상 완료

POI 관련 화면 (3.1 / 3.5 / 7.5)
  ├─ POI 목록 조회·연결 UI는 1차 개발에 포함된다.
  └─ 실제 Temi POI 조회 대신 FakeRepository의 샘플 POI 데이터로 동작한다.
```
